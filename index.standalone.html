// STUDI KASUS TEKNIS — SISTEM ABSENSI ASN

Membangun Untuk
Skala Nyata

"Bedah teknis mengurai bottleneck konkurensi, eliminasi database locking, dan restrukturisasi caching layer."

Mobile App → Nginx → PHP-FPM → Redis Queue → MySQL

[01 // MASALAH]

Morning Spike Concurrency

18,000+ request/menit pada jam 07:00–07:30 ketika seluruh ASN melakukan presensi serentak — server lama collapse dan menghasilkan error 504 berulang.

[02 // PENDEKATAN]

Decoupled Ingestion via Redis Stream

Request presensi tidak lagi menulis langsung ke MySQL. Seluruh ingestion di-dekouple melalui Redis Stream sehingga lonjakan pagi terserap oleh buffer.

[03 // ARSITEKTUR]

Queue & In-Memory Buffer Layer

Worker antrean memproses data secara batch ke database. Lapisan buffer in-memory mencegah thundering herd pada koneksi MySQL.

[04 // TANTANGAN]

Double Submission & Race Condition

Koneksi seluler yang tidak stabil memicu request kirim ulang. Tanpa guard, satu presensi bisa tercatat ganda — race condition klasik pada skala ribuan perangkat.

[05 // SOLUSI TEKNIS]

Redis Distributed Lock

Mutex Redis NX PX 10000 menjamin satu request presensi dieksekusi tepat satu kali — idempotent terhadap retry dari perangkat.

[06 // HASIL TERUKUR]

Stabilitas Skala Penuh

Eliminasi 100% error 504 pada jam puncak, peningkatan SLA ke 99.98%, dan sistem tetap responsif saat 40,000+ concurrent user aktif.
